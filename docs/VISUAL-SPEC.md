# Grove 视觉与交互规范草案

版本 0.4，2026-11-02，按已批准草案分批实施中。原始评估基于首个清理快照；实现状态与待校准建议在下文分别记录。优先级按排版、图标、对齐、色彩与组件状态排列。

## 依据与边界

视觉观察来自 Windows 本地验收时实际查看的源码浏览、关于窗口、宽窗 diff＋Log、窄窗、聚焦和工作树页面。部分复杂场景截图采集于品牌改名前，仍显示 GX；当时与当前快照的布局、字体、色彩和间距一致。

这些截图可能含本机路径与项目内容，未纳入清理后的源码仓库，也不提供失效的本地材料链接。因此，下文的截图观察保留为评估记录，外部读者无法仅凭此仓库独立复核，应在实施前用自己的隔离样本重拍校准。现有实现可通过后文源码链接核查；数字规格属于建议，不是已完成的验收结果。

已查看像素的参考：[Zed outline](https://zed.dev/img/outline-panel/singleton.png)、[Sublime 官方图](https://www.sublimetext.com/images/og-full.jpg)。Zed 此图是浅色界面，可借鉴的是灰阶背景、细分隔和正文优先的关系，不据此更换 Grove 深色方向。Sublime 图可确认箭头、图标、名称的稳定列；图中没有可验证的 Git 状态列，右侧状态列规格是对 Grove 的建议。GitHub 以字重和留白分组的方向来自本轮调研输入，未另采其弹层像素。

以下“观察”来自截图，“源码”来自实际样式／状态逻辑；不能把源码风险当作已观测故障。原评估使用工具原始截图，未裁剪或重绘；鼠标标记不属于产品界面。原截图 DPI 未核定，数值规格使用原生 DIP／Web CSS px，分别实测缩放，不按图片像素直接套值。

## 实施状态

第一批已实现基础文字／状态角色：工具标题使用稳定的 Medium 字重；通用图文构造器与 Web 工具项间距为 6；原生图标描边收敛为 1.5；原生／Web 对应的辅助、禁用与焦点颜色一致，禁用文字不再重复叠加透明度；组内历史分隔使用 SubtleBorder。原有字号、文件行高和代码密度保留。

第二批将文件名改为占用剩余空间，图标与状态使用固定列；列表小于 420 DIP 时隐藏父路径，完整路径仍可通过提示查看。Diff 版本条把只读状态、等宽修订号与路径分层，编辑区小于 850 CSS px 时隐藏路径。About 按内容定高；Reset 的分支、目标 SHA、摘要、作者分层，正文可滚动，底部动作保留；工作树分支、状态、路径与 SHA 的字级和间距已统一。

第二批在同一隔离仓库完成宽窄窗口、中文长文件名、项目树和改动列表、About 关闭焦点、Reset 四模式键盘切换及默认 Enter／Escape 取消、两个工作树选择与取消检查。About 从 582×423 收敛为 522×219 像素；Reset 因增加层级和间距由 542×430 变为 542×503，仍完整适配 884×640 测试窗口。两批截图中的标签数和滚动位置可能不同，不将这些差异计入排版收益。Core 456/456、Editor 73/73、零警告构建和 Windows self-contained 发布资源检查通过；此处不代表更新后的 macOS GUI 或 hosted CI 已验收。

Windows 已完成 1382×899／884×640 实际截图、输入焦点、中文文本查找、Esc 返回及 F7 定位检查；Core 456/456、Editor 73/73 和零警告构建通过。截图是本地验收材料，不纳入源码仓库。窄窗截图含 F7 后的不同滚动位置，不据此声称代码行数增加。

当前应用仅提供固定深色主题。浅色、真实 IME 组合输入、跨 DPI、屏幕阅读器及 macOS GUI 未在此批验收。第二批已实现文件树列位、Diff 版本元信息、About／Reset 的内容层级与工作树行排版；下表中尚未落地的规格仍为待校准建议。

### 非模态工具与项目树定位

Git 命令输出与任务状态合并为主界面底部工具页，隐藏面板不停止写入；终止进程仍单独确认，并绑定原任务与 PID。Worktree 列表成为同一停靠系统中的工具页，支持刷新、当前／不可用状态和打开已有目录，重新校验目录与共用 Git 元数据；切换后刷新当前标记，隔离旧仓库输出。默认不新开窗口，保留用户主动浮动工具页的已有能力。

项目路径筛选默认收起；图标或项目树内 Ctrl+F 展开。有条件时输入与清除入口持续可见，点击图标不会隐藏活动条件；空输入可用 Esc 收起。定位图标或 Ctrl+Shift+E 展开祖先、选中并滚动到当前主编辑器文件。文件历史页有自己的定位入口和快捷键，使用自身已发布文档路径；两种入口都保留编辑器版本、历史提交与 Diff 视图。筛选阻挡、文件不存在或工作树不匹配时显示明确提示，不自动清除条件或选另一个文件。

Windows 在 1382×899／884×640 实际窗口验证主界面输出、Worktree 选择／切换及输出隔离、筛选与清除、主编辑器／独立历史定位；121 个测试文件中末尾的长中文名可滚动到可见。Core 464/464、Editor 73/73、零警告构建及自包含发布检查通过。本机 IME、DPI、浅色与 macOS GUI 的边界不变。独立文件历史仍为单会话；多文件标签只做兼容性评估，尚未实现。

## 具体问题与落地规格建议

| 优先级／位置 | 具体依据 | 建议规格与验收 |
| --- | --- | --- |
| P1 · 文字层级 | 观察：宽窗中工具标题、文件名、路径与按钮文字密度接近，主次主要依靠边线。源码：12.5 与 12 仅差 0.5 | 保留现有字号；正文 400、分组 500／600，元信息用 Secondary／Muted。将同屏正文、组名、路径、计数各映射一个角色。用中英文同屏检查视觉层级，避免靠整体放大字体解决 |
| P1 · 边界与色彩 | 观察：diff、文件列表、工具条、Log 同开时，多条横纵分隔同时争夺注意；导航文字比部分代码默认文字更亮 | 主停靠分界保留 Border；同组分隔改用 SubtleBorder 或间距；激活标签保留单一强调线。先统一 token 角色，再用同一复杂 diff 对照，检查正文成为第一阅读目标。当前没有对比度合规测量，不宣称颜色不合格 |
| P1 · 对话框排版 | 观察：关于窗口中几行文字集中在顶部，其下有很大的空白；正文中的产品名、位置标题和路径同等重量 | 简短信息窗口按内容定高，建议宽 480–560、正文内边距 16、组间 12、标题 14/600、路径 12；长帮助／日志保留上限和滚动。以实际内容决定高度，分别验收关于、错误详情、Reset，不能统一缩小所有窗口 |
| P1 · 文件树列宽 | 观察：宽窗改动列表把文件名、父路径、状态放在一行，空间较挤；源码：名称 Auto 且 MaxWidth=180，父路径占剩余，ChevronWidth 按行变化 | 同层保留稳定的展开位 14、图标槽 20、状态槽 18；文件名优先占剩余，父路径设上限并在窄栏隐藏，完整路径保留提示。用 MD／C#／PY／TSX、长名、中文、目录和冲突行检查。具体“长名过早截断”目前是源码风险，需专门样本验证 |
| P2 · 图标光学重量 | 观察：原生轮廓图标、文件类型字母和 diff 中的 » 动作在同屏重量不同；已有原生／Web 图标几何并非完全分裂 | 继续用 16 格／1.5 线；动作图标在 28 点击框内居中，图文间距统一 6；类型标记使用固定槽和明确基线。优先把文本动作符号纳入现有几何，不新引入第三套图标 |
| P2 · 间距与对齐 | 观察：复杂窗口中多层标题／工具条连续堆叠，短标签和图标密集；源码含 4、5、6、8、12 等局部间距 | 间距档 4／8／12／16／24，图文 6 作为固定光学间距。文件行 22、Log 行 24 保持；组内控件按同一垂直中心和基线排列。用一张含标题、筛选、图标、文件、状态的组件页核验，不逐控件随手加 Margin |
| P2 · diff 元信息与小地图 | 观察：1382 宽窗仍有行内表达式裁切，小地图和多层版本条占据明显空间；窄窗已有聚焦与 <500 隐藏小地图 | 版本条固定为来源／SHA＋路径＋状态三类，元信息同一字号、基线和省略规则；两侧高度相同。建议增加可见的小地图显示偏好，在代码宽度受限时收敛辅助元素；暂不改计算或并排语义 |
| P2 · 工作树列表密度 | 观察：当前／锁定／不可用标识已比旧版清楚，名称与右侧状态对齐；每项路径和第三行 SHA 仍形成较高行块 | 保留已修正的语义与右侧状态；名称 500、路径 12、SHA 11 等宽，行内 4、行间 8；长路径省略且可查看完整值。失效原因与 SHA 分开角色，不能用灰度降低到无法读出 |

## 组件状态规则建议

| 组件 | 正常／悬停 | 选择／键盘焦点 | 禁用／错误 |
| --- | --- | --- | --- |
| 工具按钮 | 默认辅助色；悬停只改变所在点击框 | 保留独立焦点环；“已开启”使用持续状态，不能与 hover 相同 | 图标和文字同步；原因可通过提示／可访问描述获知 |
| 文件行 | 名称主文字、路径次文字、状态占固定槽 | 复用已有蓝色焦点选择／灰色非焦点选择；“已打开文件”建议另用低强度标识，不占用 Git 状态位 | 冲突／失效保留文字含义，不只依靠红色 |
| 标签／Log | 激活标签强调一次；作者、日期、引用比主题弱 | 激活文档、当前树焦点、当前提交分别呈现；不因鼠标移走抹掉选择 | 无结果保留条件与清除入口；避免空白区域只能猜原因 |
| 对话框 | 上下文、内容、动作三组；外 16，组间 12，按钮间 8 | 取消／默认／危险动作保留各自既有键盘约定；视觉规范不重设 Reset 默认焦点 | 错误靠近对应输入或稳定反馈位；详情可阅读／复制，避免推动主布局 |

上述表是建议。当前已有 hover、焦点环、非焦点选择和固定错误状态栏；“已打开文件”独立标识尚未存在于 FileNavigationRow。规范实施时需检查鼠标、键盘、非活动窗口、加载、空结果、失败各状态，而非只验一张正常截图。

## 分批实施与验收建议

先建立同一组 native／Web 组件样本：字体、图标、行、菜单、按钮、输入、状态；落地文字角色、边线层级、图文基线与关于窗口。其次整理文件树／Log 列、Diff 版本条、工作树／Reset 共用对话框间距。统一位置栈、单栏 diff、历史内容搜索另作功能项，不塞进视觉规范首批。

每批用同一仓库、文件、版本、字体、宽窗 1382×899 和窄窗 884×640 的原始截图对照；实际窗口缩放／DPI另记。样本包括长英文、中文、emoji、PY／TSX／MD、长路径、脏 worktree、空结果、禁用及错误；检查行高、基线、末端状态列、截断、焦点与选择。Mac、混合 DPI、对比度数值和屏幕阅读器需要独立验收，不能由当前 Windows 截图推断。
