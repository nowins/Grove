# 开发约定

Grove 当前是个人本地 Git 与代码查看器。核心在 src/GitX.Core，Avalonia 桌面壳在 src/GitX.Desktop，离线 Monaco／Tree-sitter 在 Editor 子目录，真实 Git 集成测试在 tests/GitX.Core.Tests。包版本和运行时图由项目及锁文件维护。

## 空工作区与状态提示

关闭最后一个文件或全部标签后，进入无文件标签的空工作区；不显示“文件：选择文件”及其关闭按钮，也不保留文件工具栏。中央只保留搜索文件／查找内容／最近文件三行入口，16px 提示字号、两列对齐，使用已有命令与平台快捷键。主窗口同时发布 WorkspaceActions 能力与语义上的 EmptyWorkspace 标记；只有正常空态省略“选择文件查看内容”，真实错误／失效通知继续显示，不能按提示文案猜测状态。独立 Diff／历史窗口不提供不支持的工作区操作；按钮核对文档代次、加载状态与 DOM 所有权，过期元素不发送命令。

标签栏的回退文件标题只用于有实际文档路径且没有正式标签的窗口；没有文档路径的通知和连续 Diff 不伪装成文件。仍有真实文件标签时继续保留标签。空工作区聚焦容器，不自动高亮第一项；Tab 进入按钮并保留可见焦点，不转移到已经无模型的编辑器。提示使用文本节点，保持现有主题与版本校验。

## 阅读区与工具窗口入口

顶栏分支选择器先展开搜索与加载提示，只用 BranchCatalog 读取分支引用和跟踪关系，不在展开前扫描状态、哈希工作文件、枚举 Stash 或启动 worktree 命令。进入具体分支操作／新建分支时，才并行读取完整 ActionContext 和 worktree 登记，并复核所选分支完整记录；保留脏状态、进行中操作与其他 worktree 占用的禁用规则。列表不缓存到下一次打开。关闭弹层取消只读任务；返回列表退役操作页请求，迟到结果不能重开或替换新弹层。动作输入／确认后还须复核仓库代次，写入继续在锁内检查原 token，读取取消不传递给 Git 写入。

Git Log 提交右键的读写动作绑定打开菜单时的仓库代次、历史代次和完整提交 SHA；异步读取、选择父／子提交及输入／确认后均复核归属。创建分支／标签及检出另在仓库写锁内复核实际仓库 token，读取取消不终止已开始的 Git 写入。提交目标不伪装成 BranchEntry，也不从菜单显示名重新解析修订。

从提交新建分支复用分支输入窗口，可选创建后检出；仅创建引用允许脏工作区，检出要求干净状态。任意提交分支不设置隐式远端跟踪，不覆盖同名引用。标签入口明确创建本地轻量标签，关闭隐式签名，不推送。分离 HEAD 检出有明确确认；检出及创建后检出均拒绝覆盖忽略文件，不强制、不递归更新子模块。原分支及其他 worktree 保持原样。

提交补丁是完整提交相对父提交的 Git binary diff，不是邮件格式；初始提交以空树为起点，合并提交须选择真实父提交。固定 a/、b/ 前缀，禁用外部 diff／textconv／颜色／相对路径，按单字节映射保留非 UTF-8 内容。复用有界 Git 读取，超过 2 MiB 输出时失败，不导出截断结果。系统保存窗口返回后仍复核原菜单归属。

父子导航属于独立 Git Log 工具，不要求编辑区处于历史模式，也不切换工作区修订。子提交沿实际图边从分支、标签和 HEAD 的可达历史读取，排除 stash／恢复引用；多个候选显式选择。已加载目标直接选中；隐藏或未加载目标按现有游标分页定位，找到前不替换列表，找到后一次发布并清除历史筛选、说明状态。换仓、换筛选、改变选择或发起新跳转后拒绝旧结果。

“浏览此修订的仓库”在项目工具中临时展示固定完整 SHA 的只读目录浏览器，不执行检出，也不复用工作区文件清单。每次只读取一个 Git tree 的直接条目，目录优先并按字面名称排序，每页 500 项，可加载完整目录；目录展开才读取下一级，不预读 blob。链接只标注类型，不跟随磁盘目标；gitlink 不进入外部子模块仓库。文件复用现有历史源码标签，返回工作区只切换侧栏，保留已打开的版本标签。重新开仓或换仓关闭快照浏览；读取复核仓库／SHA／目录／分页代次，关闭后不发布迟到结果。Enter 和 Alt+Up 使用列表隧道路由，不被 ListBox 的默认键盘处理截断。

批量 Cherry-pick／Revert 支持 1–100 个不同的完整提交 SHA。计划按真实拓扑排序，拣选从旧到新、撤销从新到旧，不依赖作者时间或筛选后的显示顺序；确认窗口完整展示执行顺序。写锁内重新读取计划、比对顺序及仓库 token，再以单次 Git sequencer 执行全部提交，不能循环调用单提交操作冒充整批。合并提交显式选择统一主线序号；普通提交与合并提交混选时只允许主线 1，不兼容的主线在写入前拒绝，需分开操作。冲突或空提交停止后保留剩余队列，继续／跳过／中止交给 Git；中止退回整批起点。跳过保留可能被丢弃的工作文件副本；跳过／中止确认绑定打开时的操作 token 和仓库代次，外部完成并开始新操作后不能沿用旧确认。

历史整理只操作当前检出的本地分支。重放限所选提交至 HEAD 的最近 100 条线性历史，拒绝范围内合并提交；以本地 `refs/remotes/` 的可达性判断已发布状态，不联网推测。写锁内重新读取范围、token 与 worktree 占用；原 HEAD、索引与工作文件按现有 HistoryWriter 保存恢复记录，不自动 Stash，不自动更新其他分支。Squash／Fixup 快捷入口要求连续选择，单选时包含上一提交；Drop 可选多条，不能删除仓库全部历史。

HEAD 的“只改说明”使用原树、全部父提交与原作者创建替代对象，再以旧 SHA 条件更新当前分支引用；保留真实索引字节和工作文件，不复用会包含暂存内容的 Amend，也不触发普通 commit 的提交钩子。非 HEAD 说明修改使用 Reword 重放后续提交。Undo Commit 仅支持单父 HEAD，以 Soft Reset 保留索引及工作文件；根提交／合并提交仍使用明确的 Reset 入口。

交互式窗口逐条提供 Pick／Reword／Squash／Fixup／Drop 及上下移动；打开时默认取消，不把 Enter／说明换行绑定为执行。计划必须恰好包含原提交集合一次，无变化、首条 Fixup／Squash、空说明和超额输入在写入前拒绝。Git 自身的 interactive sequencer 执行真实 todo；只生成已验证动作及完整 SHA，不接收任意命令。序列编辑器仅使用 Git 自带 shell 的内建 printf，路径按 shell 单引号规则引用；说明保存在恢复目录的 UTF-8 文件中，作为数据读取，不拼入命令。

Reword 按 Git `done` 中的实际提交读取对应说明；暂停后在 rebase 元数据中保存原 HEAD、恢复 ID、说明摘要及注释字符，后续继续／跳过重建编辑器，校验文件类型、大小、摘要及归属。注释字符选用所有原说明和新说明均未使用的行首字符，避免 `#` 正文被 Git 清理；与换行规范化使用同一规则。重放保留原空提交，新变空的改动暂停；现有操作栏支持 rebase 继续／跳过／中止。操作 token 同时涵盖 todo、done、原 HEAD、分支名及本工具恢复元数据；旧确认不能继续变化后的队列。原生 Git 行为参照 [rebase](https://git-scm.com/docs/git-rebase)、[commit-tree](https://git-scm.com/docs/git-commit-tree) 与 [IDEA 历史整理](https://www.jetbrains.com/help/idea/edit-project-history.html)。

源码页不显示结构／文件历史／保存／笔记工具行；文件结构、文件历史及添加／查看本地笔记通过代码右键菜单进入。Markdown 预览右键可回到源码，源码右键可恢复预览，Esc 仍返回源码；菜单动作绑定打开时的文档代次，切文件或加载后旧菜单不能操作新文件。Diff 的差异导航、空白和高亮工具栏保留。

编码、BOM、换行与保存状态复用已有编辑状态，通过 editor-status 发送到主窗口底部统一状态栏。消息限制为当前发布与文档版本、最多 1,024 字符，发布新文档时先清空；不增加编码转换能力，也不从只读快照猜测编码。保存继续使用已有快捷键与菜单，错误和未保存状态仍可见。

工具入口统一使用侧边图标；Top／Left 入口在左上，Bottom 入口在左下，Right 入口在右侧。按钮位置与面板展开方向分开，Bottom 面板仍横向展开。区域顶部仅显示当前工具标题及选项／隐藏操作，移除重复的多工具标签条；切换使用侧边图标及原快捷键。工具 ID、ToolEdge、布局版本及重挂载保护不变，拖动排序按真实纵向图标位置计算，既有四边布局配置继续可读。

文件监听分两层验证：原生测试要求实际写入路径被失效，并以通知刷新真实 Git 状态；不假定原位写入只有 Changed 通知。macOS 的 [FSEvents 会合并相邻事件](https://developer.apple.com/library/archive/documentation/Darwin/Conceptual/FSEvents_ProgGuide/TechnologyOverview/TechnologyOverview.html)，runner 已观测到 `FileMode.Open` 写入同时收到 Changed 与 Created，完整刷新是正确回退。失败附带原生事件与刷新批次。增量路径、混合元数据与结构事件的批次规则另用 internal 事件输入验证，仅关闭原生事件源，保留真实定时器、Git 索引和忽略规则；严格断言纯内容保留路径、元数据／结构事件完整刷新。不按平台跳过，也不把允许安全回退表述为 Mac 增量性能已验收。

## 全量／增量状态一致性

原生全量枚举在 Windows ARM64 对中文及方括号路径曾同时报告删除与未跟踪，单路径读取则报告修改。全量读取只对**完全相同的字面路径**出现这两类矛盾状态时复核：索引必须是普通文件，磁盘文件存在且通过现有路径／链接检查，再使用 LibGit2Sharp 的字面单路径 API 重读；索引状态还须与枚举结果一致。复核后每路径只发布一条状态，内容已恢复到索引时移除虚假的工作区改动，独立暂存状态保留。

不把不同大小写路径合并，也不靠合并状态标签猜测结果；目录、缺失、符号链接／gitlink 索引、冲突、重命名或索引读数不一致的情况不进入这条修正。普通枚举无额外文件读取，不加入外部 Git 扫描；现有读取前后 HEAD／索引／操作代次复核保留。库内部导致两种枚举分歧的原因尚未定位，不把此兼容修正写成已确认的上游编译器／Unicode 根因。

增量与全量一致性测试另外核对 `git --no-optional-locks --literal-pathspecs status --porcelain=v1 -z`，明确工作区与暂存区各自状态。模拟矛盾原生条目的回归仍使用真实临时仓库、实际单路径读取和 Git 对照，并检查 HEAD、索引字节及工作文件不变；注入形状测试不能替代 Windows ARM64 原生 CI。

## 连续 Diff 阅读（2026-11-07）

主编辑区的“连续 Diff”、视图菜单和 Actions 打开当前本地改动或历史比较范围。复用同一 WebView、字体、行高及深色颜色；按文件排列两侧文本、真实行号、比较标签、换行和存在状态。未变区只保留两端各 3 行并标明省略；只做按行差异高亮。每文件可打开完整 Monaco Diff，双击行号定位对应侧与行；查找、F7、折叠、暂存和评论继续在完整 Diff 操作，不在连续阅读视图创建第二套编辑能力。

ContinuousDiffSession 捕获精确条目、比较类型、旧路径、完整提交及空白选项；HTTP 只能用当前随机会话 ID、文档版本与文件编号读取，不能提供任意路径。每页 200 个文件，可翻页遍历范围；不预读正文。读取、投影和 JSON 序列化离开 UI 线程，同一窗口的连续范围共用最多 2 个实际读取额度，刷新换代也不能提前释放旧原生读取的额度；超额拒绝而不积累请求队列，继续使用已有 Core 读取调度。服务端不缓存返回文档，不传送写令牌、编辑许可、评论锚点或 patch。

中止浏览器请求不等于后端原生读取已经退出，不能立即归还服务端额度。暂时繁忙返回 429 和 Retry-After，浏览器最多自动重试 5 次，不把繁忙响应缓存成文件内容；仍失败时保留手动重试。关闭／换代清除重试定时器，旧重试不得启动新范围的读取。

手动重新读取先中止本文件的旧请求，清除其退避定时器、正文 DOM、侧标题及缓存引用，再安排新请求；保留高度／行数元数据以稳定滚动位置。失败时不得继续显示上一捕获的代码或行链接。已中止请求即使晚到也不能替换新结果；浏览器的执行计数仍由实际 Promise 完成时归还，不因按钮点击重复释放额度。

工作区比较绑定打开时的 HEAD／索引／Git 操作状态指纹，每文件读取前后复核；历史比较按完整 SHA 读取。磁盘正文逐文件读取，不宣称所有工作文件是同一瞬间的原子快照，也不包含未保存草稿。换仓、打开完整文件或显式打开其他范围会退役原会话；刷新可变范围时先从新快照重建文件列表，再替换会话 ID／文档代次，旧请求仍拒绝发布。返回和 JSON 序列化完成后再次核对会话所有权，过期 HTTP 返回 404。失效、缺失、二进制及读取失败给出说明和重试入口，不伪造空文本差异。

连续视图不创建 Monaco 模型，保留原标签拥有的草稿和撤销栈。浏览器最多缓存 8 个文件、估算 16 MiB 的已解码行数据，仅绘制视口附近的行；请求上限 2，离开视口的请求中止，关闭／换代释放所有文件数据、DOM 和待执行帧。卸载文件保留高度和行数元数据以稳定滚动锚点，重新进入按需读取。每文件投影最多 6,000 个展示行（含上下文与省略行），超出明确提示并保留完整 Diff 入口；每页高度因此仍在浏览器布局范围内。上述预算不是完整应用常驻内存或 FPS 指标。

连续视图为当前文档代次拥有的临时阅读状态，不建立正式文件标签或独立阅读历史项；Back 返回进入前的文件位置，打开完整 Diff 后按原文件导航规则记录位置。可变范围刷新保持稳定的 Scope 标识，前端只保留文件高度和阅读锚点，清除旧正文；按文件路径及原侧行号恢复位置，文件移除则选邻近存活文件。等待新正文期间用户滚动会取消延迟恢复。范围变空仍保持连续视图，后续变化可重新出现。不可变历史范围不受普通工作区刷新或历史工具选择影响；与工作区比较的历史范围继续绑定原 SHA，分页也沿用原比较而不读取后来切换的工具范围。关闭已有标签仍经过原有草稿保存／放弃／取消保护；连续视图不拥有或保存这些草稿，不增加视觉改版、IDE 索引或多文件编辑。

## 完整 Diff 跨文件导航（2026-11-09）

主工作区 F7／Shift+F7 和上一处／下一处按钮在文件边界沿同一比较范围移动，分别定位下一文件首块或上一文件末块；范围末尾整体循环。二进制、提示和没有文本块的条目跳过，不建立中间文件标签；当前文件变干净后从其路径继续。独立 Diff 窗口保留文件内循环。历史标签只保留原范围的轻量条目，缺少范围时按该标签的完整提交 SHA／比较端点按需解析；不使用后来选中的日志提交，也不预读所有正文。工作区范围从最新快照产生，不给每个本地标签保留一份完整清单。

跨文件读取一次只运行一个请求。发布前核对仓库、文档、注解、阅读意图、标签、空白模式及 HEAD／索引指纹，切文件、换仓、刷新或取消后的旧结果不得覆盖新状态；离开编辑区后不抢回原生焦点。桥接只接收方向、侧和当前代次，不接受文件路径。刷新文档的代次递增不依赖事件订阅者。只读验证使用 `git --no-optional-locks status`，避免验证命令本身刷新索引 stat 缓存。

## 阅读位置前进／后退（2026-11-07）

主工作区按仓库会话保留最多 100 条阅读位置，只存路径、比较类型、完整提交 SHA、旧路径、Diff 侧及行列，不保留正文、模型或草稿。换文件／修订以及鼠标、查找、跳行和结构定位建立导航点；输入、方向键和撤销只更新当前位置，同一行的定位不新增记录。同文件同侧相距不足 4 行的离开位置合并；返回后新跳转清除前进分支，普通光标移动保留前进分支。换仓（包括重开同一路径）和窗口释放清空记录，不落盘。

Windows／Linux 使用 Alt+Left／Right，macOS 使用 Command+Option+Left／Right；菜单和 Actions 共用可执行性判断。仅主编辑器启用，独立 Diff／文件历史保留原有行为；Log 没有可返回阅读位置时保留原快捷键返回日志的路径。Monaco 的鼠标跳转为 Explicit，公开 setPosition/setSelection（包括内置 Find）为 API/NotSet，不能只按 Explicit 识别。载入、视图恢复和折叠调整不得产生新导航点，IME、查找／评论输入及跳行／结构弹层持有输入时拒绝阅读导航。

离开文档前可从当前已发布 WebView 捕获实时行列（原生查询上限 250 ms、JSON 上限 2 KiB），并核对仓库及文档代次。普通打开在捕获失败时使用已知位置；前进／后退在捕获不可用时拒绝执行。返回先读目标，核对读取意图、仓库、文档、注解和历史代次后才改变标签、文档和历史游标；缺失、错误、取消或过期保持当前上下文。关闭活动标签同样捕获位置并拒绝过期结果，关闭全部后 Back 可重开最后位置。

历史源码绑定固定提交及其真实路径（含 Blame 上一修订的重命名前路径），保持只读；当前文件和本地 Diff 重新读取实时内容，行列由实际模型校验。复用相同标签的编辑模型和撤销记录；历史记录本身不拥有模型。Diff 恢复选中侧，并展开目标所在的未变区域，其他折叠保持已有状态。本批不增加阅读历史面板、连续 Diff、跨文件语义分析或视觉改版。

## 文件搜索与性能回归（2026-11-07）

文件搜索复用当前仓库快照的文件清单，不建立项目级符号索引。支持连续子串、缩写/子序列、空格分词、路径分段、前导 `./` 和 `:行[:列]`；正文搜索保留原有字面/正则语义。完全文件名、无扩展名全名、前缀、子串、缩写、路径匹配依次排序；同层级才使用当前 worktree 的工作区最近文件顺序，历史版本记录和不在当前清单内的路径不扩展搜索范围。只保留最好的 1,000 个候选，稳定比较完整路径，不对全部命中排序或缓存正文；取消仍由有界读取调度器控制。

All 搜索先发布文件结果，再追加正文结果，合计仍最多 1,000 条。最终结果必须保留文件前缀，使用同一个可观察集合追加，不替换已有行或重置选中项。打开部分结果取消剩余读取；查询变化/关闭拒绝旧回调，最终失败清空当前结果并明确报错。读取和发布错误均观察底层任务，不遗留未观察异常或提前归还不可中断任务的额度。打开搜索前读取最近记录也核对仓库会话代次；最近记录读取失败不阻止搜索。预览、打开及文本指纹校验沿用原规则，未增加 Git 写入、导航历史、连续 Diff 或视觉改版。

`pwsh tools/perf.ps1` 创建全新 `artifacts/perf/` 输出及专用 Git 样本仓库，覆盖 20,000 个文件名、1,001 个磁盘文本文件、All 首批/完整结果、仓库扫描、21 条历史、结构化 Diff 和源码读取。默认每场景预热 3 次、测量 9 次，记录全部样本、最近秩 p50/p95、探针进程 CPU、托管分配及输入/结果/程序集 SHA-256。9 次样本的 p95 等于最大样本值，不是大样本的稳定尾延迟估计。正确性断言、缺失数据、预算超限、基线环境/输入/结果不匹配均失败退出。

绝对预算及相对容差在 `tools/PerformanceProbe/budgets.json`，短耗时/CPU 与分配另有绝对噪声下限。基线要求同机、OS、架构、运行时、处理器数量、采样次数及相同场景/输入/结果。改变预期行为或样本时先审阅差异，再保存新基线，不能忽略结果指纹变化直接比速度。正式计时串行执行，避免与构建、全量测试、浏览器或其他性能批次重叠；先后两次通过只证明工具可重现，不证明产品相对旧版加速。

本入口不启动窗口/WebView，不测输入到绘制、滚动帧率、标签切换、完整进程树内存或空闲 CPU；CPU 不包含 Git 子进程，计时器粒度可能产生零 CPU 样本，托管分配不是常驻内存。输出和原始证据保留在忽略目录；工具与预算属于工程，机器生成报告和样本仓库不纳入源码。

## 分支创建与检出

## Markdown 阅读

识别 `.md`、`.markdown`、`.mdown` 和 `.mkd`。单文件 Markdown 阅读默认显示预览，右键可切换到源码。预览与源码分别保留滚动位置；源码中的搜索或行定位会切回源码，预览中的 Esc 也返回源码。Diff 保持文本对比，不把渲染结果当作行级差异。

Marked 负责 GFM 解析，DOMPurify 使用明确的元素与属性白名单净化结果。原始 HTML 按文本显示，不接受样式、脚本、表单、SVG 或嵌入页面；代码块仅以等宽文本呈现。所有运行资源离线打包，并随包附带相应许可证。

图片只通过每窗口的随机 loopback 地址读取，绑定已发布文档的版本、仓库、路径与修订。仅支持 8 MiB 以内的仓库内 PNG、JPEG、GIF、WebP，拒绝符号链接、目录联接、Git 元数据、越界与无效路径。历史图片来自对应提交，当前 worktree 图片来自该 worktree。切换文档后旧版本地址失效。远程图片、SVG 与 data URI 不自动加载。

链接点击走校验版本的原生桥接：仓库内相对路径在当前文件目录解析，历史链接保留同一提交；缺失、超限或不安全目标不替换原文件。HTTP/HTTPS 网页仅在用户点击后交给系统浏览器，拒绝带凭据的 URL 与其他协议。当前不支持本地链接的查询参数、仓库根绝对路径、原始 HTML 锚点或 Markdown 扩展插件。

相关测试在 MarkdownTests 与 markdown-preview.test.js：覆盖渲染、注入与不安全协议、中文路径、重复标题锚点、切换/搜索、过期消息、图片格式/大小、历史及 worktree 隔离。Git 验证全部使用测试创建的临时仓库。


## 历史引用筛选与源码跳行

历史列表工具栏的分支筛选只改变历史查询范围，不调用 checkout。引用身份使用完整 canonical ref，显示名相同的本地分支、远端分支及标签不得合并。最近记录和收藏按工作目录分别保存；失效引用不再提供，选择前再次核对当前候选。搜索或方向键选中不能直接应用筛选，Enter 或显式点击才应用；星标和列表 Space 只改变收藏。

引用偏好写入使用本地原子替换，保留不支持版本或超限原文件。重建虚拟列表前将焦点留在弹层内，布局后仅在根目录、弹层代次、输入代次及搜索条件仍一致时恢复，防止移除焦点行导致下层 WebView 激活和弹层意外关闭。

源码 Ctrl+G 打开跳行输入；macOS 另提供 Command+L 原生菜单快捷键，同时保留 Ctrl+G。输入不移动光标，Enter 校验当前显示模型的真实行数，Esc 取消；空值、非整数或越界值原位提示，不静默截断。历史版本使用历史模型行数，Markdown 菜单定位先返回源码。打开表单时捕获文档代次、路径、模型及文本版本；切换文件、重新加载或关闭窗口后旧定位失效。原生菜单命令继续复用上下文检查，不能把编辑器中其他输入框的键盘操作当作源码跳行。

Mac CI 的 ChromeProbe 使用自身 AppKit 窗口队列发送 Command+L、Ctrl+G、Enter、Esc、方向键和 Space，检查实际 WKWebView/原生弹层的焦点与行为；输入框文本由测试设置，不冒充物理键盘输入或 IME 验收。探针只在生成的临时 Git 仓库和 linked worktree 中建立提交、引用与测试配置，并核对 HEAD、分支、索引及源文件未被导航操作改变。单个搜索结果按方向键时先进入当前结果，确保 Space 可收藏，不因越界而留在搜索框。

## 文件标签上下文菜单

普通文件、比较及历史源码标签的上下文菜单始终针对被点击的 tab ID，不因右键而切换文件。支持关闭标签、关闭其他、关闭全部；单标签时禁用关闭其他。Mac Control-click 不退化为左键选择或关闭按钮动作；Shift+F10/ContextMenu、方向键、Home/End、Enter/Space、Esc 可操作或取消。菜单复用现有浮层样式及视口定位；外部点击、滚动、失焦、载入或 tab 集合变化将取消旧菜单。

批量关闭在视图模型中一次确定保留集合，仅在活动标签实际被关闭时加载一次保留目标；保留活动标签时不发布新文档或重置视图。桥接及后端均核对文档版本和精确 ID，目标已消失时关闭全部也拒绝执行。清空文档必须在可空事件调用外递增读取代次，避免没有事件订阅者时旧读取恢复已关闭页面。

## 工作区文本编辑与系统位置（2026-11-04，本地）

仅普通 WorkingFile、当前工作树且严格 UTF-8 的可预览文件具有 Editing 元数据。基线绑定工作树根、路径、HEAD、原始字节 SHA-256、时间/长度/属性及 Unix mode；BOM 与均匀 LF/CRLF 单独保留。混合/单独 CR、无效编码、NUL、超过预览限制、只读或冲突状态不给予编辑许可。历史、差异、冲突与提示文档不因路径相同而获得保存权限。

浏览器按原生标签 ID 与工作树 RootKey 保留 Monaco 模型和撤销记录；刷新/删除/外部修改保留已有草稿，关闭后才释放模型。编辑器发送小型保存意图；原生端经仅字符串的 JSON 查询拉取捕获内容，重新验证标签、根与路径，再使用 WorkingTextWriter。保存回执针对捕获的模型/撤销检查点，保存期间新增输入仍为未保存。草稿内容与已发布快照不同时停用旧 Blame/评论行锚点，Markdown 预览使用草稿。草稿仅存在当前进程内存，不宣称崩溃恢复。

写入使用现有仓库写锁、严格 UTF-8 编码和同目录私有临时文件，落盘后原子替换并检查实际备份字节，拒绝陈旧基线、删除、链接或外部改写。失败保留内存草稿及可取得的原始/冲突/捕获草稿，恢复材料位于本工作树 Git 元数据的 grove-text-recovery；不自动暂存、提交或执行强制覆盖。原子替换后还会核对分支/HEAD；若外部 Git 在此期间改变上下文，不确认保存成功，也不删除实际替换备份。无法在新上下文中安全自动回滚时，保留原文件与草稿的恢复副本，提示用户核对工作区。关闭/换仓先冻结受影响模型，确认保存/放弃/取消，重新校验标签集合与仓库代次；保存或确认失败则保留当前上下文。

文件/文件夹系统位置先校验相对路径、存在性和工作树边界，拒绝 Git 元数据及链接/联接。Windows 用 Shell 项定位；终端使用固定可执行文件及 WorkingDirectory，不拼接 cd 或路径命令。macOS 用 open -R 和 Terminal.app 的参数列表。历史标签不映射到当前同名文件。外部程序在平台验收前只验证启动计划，不视为已通过 Finder/资源管理器/终端原生验收。

## 推送前审阅（独立候选）

PushPreviewReader 只读探测实际 PushUrl 的完整目标引用，不使用 fetch tracking ref 冒充当前远程状态，不自动 Fetch。远程 SHA 本地缺失时数量为 unknown/null 并禁用推送；用户先显式 Fetch 后刷新。提交每页 100 项，文件按选择通过可取消、有 30 秒／2 Mi 字符上限的 Git diff-tree 读取第一父提交的树变化、最多展示 1000 项；不读取 patch 或工作区草稿。新远程分支列出 HEAD 的全部可达提交，不把提交数量当作实际网络传输对象数量。

快捷 Push、Commit & Push 和高级 Push 进入同一审阅窗口。异名 upstream 的快捷入口要求明确选择跟踪目标或同名目标；高级表单保持显式远程／分支选择。所有请求绑定仓库代次及窗口／文件读取代次；改目标使旧预览失效。Git 写入期间禁用再次执行和关闭，模态内可通过现有安全终止流程针对捕获的操作和 PID 请求终止；失败保留输出并要求刷新；成功但本地跟踪引用 CAS 失败仍保留 RemoteWriter 的“推送已成功”说明。不在审阅后增加通用确认。

执行仍经 RemoteWriter 的仓库锁、完整 ActionContext 校验、批准 SHA、单一目标与 tracking CAS。新增可选 reviewedRemote 参数在锁内重新探测远程，并在认证后再校验本地；普通 Push 必须先证明批准 HEAD 是已审阅远程提交的快进，再以精确 lease 固定远程更新条件，不能通过伪造预览关系绕过快进检查。Force-with-lease 仅在原高级入口明确显示历史改写含义。

远程实际端点使用 Git get-url --push 解析，再验证该结果不会被 insteadOf 再次展开；级联配置拒绝执行。预览显示脱敏实际端点，执行时重新解析比对，并以临时 remote 的 url 和显式 pushurl 固定同一值，避免 pushInsteadOf 在推送时再次改变目标。fetch/push 实际端点不同则不更新 fetch tracking。URL 显示／错误过滤多协议 userinfo、query 与 fragment。

## 未保存草稿恢复候选（205678e 独立增量，2026-11-05）

`TextDraftStore` 提供默认关闭的本机明文检查点。文件菜单显式启用；约 750 ms 合并保存所有仍存活的脏文本会话。仓库工作目录 + Git 元数据目录创建身份与相对路径隔离；Linked worktree 不共用草稿。原始磁盘 `WorkingTextEditInfo` 随记录保存，恢复不 rebasing；后续保存仍复用 `WorkingTextWriter` 的版本/权限/HEAD 检查。恢复不会直接创建或覆盖仓库文件。

每份正文 ≤1 MiB、记录集合（含异常退出遗留 pending）≤16 MiB / 64 份。有效恢复窗口 7 天；过期记录计数提示、只显式清理，不在启动时自动删除未保存内容。容量满拒绝新检查点并提示，不自动驱逐旧草稿。持久化关闭只阻止后续写入；清理是单独显式动作，可作用所有仓库。敏感路径规则在恢复窗口完整展示，但不是秘密内容检测器。

原子更换前 flush 完整 JSON，不依赖共享索引；损坏记录隔离报告。写入和删除使用存储锁及 revision CAS；异步 Save/Discard 不得移除新版。Keep 关闭及正文相等快路径还需从磁盘重新验证完整记录，不能相信内存 `_draftOwned` 缓存。Unix 目录 0700 / 记录 0600；Windows 新建目录限制当前用户，已有目录/文件须核对 owner/ACL，不接受宽权限。链接目录和记录拒绝访问。日志不包含草稿正文或私有路径。

Windows 保存暂存目录与草稿恢复目录必须在创建时同时指定当前用户 owner 和受保护的私有 DACL，再核对实际权限；不能先普通创建再修改 owner。父目录仅授予 Modify 时，后一种做法会因缺少 WRITE_OWNER 而失败。旧版失败遗留的恢复目录只有在当前用户所有、空目录、未保护且全部权限为继承 Allow 时才允许非递归删除并重新私有创建；已有内容、显式权限、其他所有者或链接继续拒绝访问，不放宽权限或自动迁移草稿。专项测试需使用仅有 Modify 的父目录，并验证 HEAD、索引和原文件保护。

正常关闭提供保存、放弃、取消，以及启用恢复时的保留副本选项。保留失败、超限、排除或副本被其他窗口删除/替换时阻止关闭。启动打开仓库仅提示待恢复数量；用户主动进入恢复窗口，选中只读磁盘/草稿对照，再明确恢复到编辑器。缺失、移动或不可读原文件仅能复制恢复副本；不自动重建。已有脏编辑器、非当前标签或身份不匹配拒绝恢复。恢复通过 Monaco edit operation 保留撤销链，保存继续走原安全写入器。

边界：750 ms 内尚未完成的输入可能丢失；模拟中断证明原子安装前旧副本保留，未声称实际断电后文件系统目录元数据持久性。完整磁盘断电、跨平台原生 ACL、IME、真实重启与多窗操作尚待验收。显式在另一窗口清理全部副本属于用户主动销毁，不能保证关闭后仍抵抗此操作。恢复对照是双栏原文，不是逐行 diff 高亮。未复制 Lithe 源码。

## Diff 执行边界与元数据复用（2026-11-06）

普通文本 Diff 在后台使用已锁定 LibGit2Sharp 原生资产的 [buffer patch API](https://github.com/libgit2/libgit2/blob/v1.8.4/include/git2/patch.h)，直接比较两份捕获文本，不创建仓库对象、临时文件或 Git 子进程。保留 Myers、零上下文、关闭缩进启发式、空白归一化及现有行/字符映射；工作区写令牌、旧结果失效和写入校验不变。

BufferDiff 独立绑定公开 C ABI，仅接受当前锁定的 `git2-5853918` / libgit2 1.8 资产，不反射调用 LibGit2Sharp 私有接口或搜索任意系统库。升级 NativeBinaries 时重新核对 ABI、原生资产与差异对照；未知版本/缺失导出走原 CLI。输入合计超过 256×1024 个 UTF-16 字符，或两侧换行计数加一的乘积超过 16,000,000，继续使用有取消/超时的子进程路径；这只是执行策略阈值，不降低预览/历史上限。进程内 native 计算不能强行中断，调用前后校验取消，返回后仍由文档代次拒绝过期结果；所有原生 patch/buffer 在 finally 释放，独立初始化引用随进程保留。

RepositorySnapshot 的历史范围、失效 token 和分支/标签列表复用同次读取的引用集合，避免再次枚举、解引用相同元数据；不跨刷新缓存可变 Git 状态。性能验收同时测后端与应用桥接完成时间；WebView/Monaco 的惰性启动必须单独衡量首次文件延迟，不能只报告未加载编辑器时的低内存。

## 仓库会话与增量失效（2026-11-06）

每次打开仓库创建独立 RepositorySession，持有快照及待处理变化；读取过程中到达的变化合并到下一批，旧会话不得覆盖新仓库。失败后下一次刷新强制完整读取。仓库清空及安装新会话均通知 Root，失败打开也不能让上一仓库任务状态留在窗口。

监听仅将普通内容变化传为有界路径集合。结构变化、Git 元数据、忽略/属性/mailmap、监听溢出、超过 64 个路径及手动刷新走完整扫描；连续事件最迟约 2 秒开始处理，已有读取仍串行完成。忽略判断的已跟踪路径集合按索引语义指纹复用，仍检查索引变化和 Git 忽略规则；按字符和每条固定开销估计超过 4 MiB 时仅供本批判断，不长期保留，不因此遗漏已跟踪的忽略路径。

增量读取仅接受原快照中已存在、索引跟踪的普通文件；前后重新检查 HEAD/索引/操作状态，路径缺失、冲突、链接、子模块、截断快照或不确定状态回退完整读取。它只优化展示快照，不提供写入授权；所有写入继续使用原捕获上下文、仓库锁及真实状态校验。手动 F5 始终重新核对全部状态。

仅变化涉及当前路径/旧路径，或完整刷新时重读当前文档；固定 SHA 历史内容不随普通工作区内容变化失效。导航集合无变化时不重建树。现有 Blame 缓存继续校验自身输入证明；完整刷新清空缓存，不能用监听路径代替保存/评论/Blame 的内容证明。

## 读取调度与进程所有权

CPU 读取与 Git 只读进程分别使用进程级 ReadScheduler，执行额度各不超过 2；CPU 额度同时不超过逻辑处理器数，每类等待队列最多 256 项，超过时显式报告繁忙。文档/预览为前台，历史/搜索/自动刷新及配置预热为后台；连续授予 8 个前台请求后允许后台推进，不抢占已经执行的任务。CPU 委托内不得再次等待同一调度器；需要 Git 回退时只获取独立的进程额度。

排队取消立即移除请求；已执行的原生调用必须等实际返回才归还额度，不能仅因调用方取消就启动更多后台工作。Git 启动、终止在后台执行，30 秒命令期限从取得执行额度后计时；取消、超时、输出超限后使用不受读取取消令牌影响的退出等待。树终止失败或 5 秒仍未确认退出时报告失败，由原进程句柄继续等待并保留额度，不能将占用的额度视为可用。此机制仅管理读取，Git 写入仍走原捕获上下文、仓库写锁与终止确认。

Diff/merge 的私有临时目录在启动前归创建者所有，交接后由 GitReadProcess 负责释放；排队取消、启动失败及正常/异常退出均走同一清理入口。只删除本次固定文件及空目录，不递归删除；短暂占用重试最多约 2 秒，仍失败时保留文件并记录诊断，不覆盖原始错误。根进程退出不等同于所有后代结束，不能据此宣称树终止一定成功。性能对照同时记录正常串行读取与取消积压场景，CPU 时间、托管分配和宿主私有内存不得替代完整桌面进程树的实测。

## 同输入 Diff 请求合并

NativeDiff 仅合并正在执行的相同计算。DiffInput 包含两侧完整原文、路径、显示标签、存在标记和空白选项；RepositoryReader 复用捕获阶段已经生成的 CommentContext.Snapshot 指纹作桶定位，其他纯文本入口在 CPU 调度器中计算哈希。捕获身份相同后仍做完整输入比较，不仅凭哈希或文件名命中。此层不访问仓库，允许两个仓库的相同输入及捕获身份复用纯计算；RepositoryReader 仍分别捕获文本、创建评论上下文、核对写入令牌，视图仍核对仓库/修订/文档代次，不共享这些状态。不要将同一机制直接用于可变工作区、HEAD、索引或未经证明的 Git 命令。

每个调用方独立等待和取消；最后一个等待者离开才取消底层工作并移除可加入的条目。旧计算后来返回不得移除同键的新计算。成功/失败结束立即移除，既不缓存结果，也不缓存错误；无等待者的异常仍需观察。CPU/Git 执行额度继续保持到实际工作返回。共享表最多登记 64 个未结束计算、估算 16 MiB 的唯一输入和 256 个等待者，已经取消但未返回的计算仍计入输入额度。输入额度不足时回到原有有界计算路径，不降低文件上限；等待者过多显式报告繁忙。这些是共享表预算，不是调用方、结果或整个进程的内存上限。

共享结果的块、行、行内跨度及单词跨度必须全部为只读集合，不能只暴露 IReadOnlyList 而继续泄露可修改的数组/List。正文和 DiffSide 保持不可变。验收同时测普通串行读取和多个调用方的重叠读取；不将人为并发收益推广为普通开文件或空闲 CPU 改善。

## 源码正文与发布元数据分离（C1）

主窗口先捕获文档、工具栏、仓库及 Markdown 资源上下文，在后台准备 EditorPublication，再核对发布序列后原子安装。准备工作不能提前改变服务器当前文档。内容身份只适用于普通源码，严格比较仓库根、活动标签、路径、语言、修订与完整正文；不能只凭路径、时间戳或摘要命中。正文未变也继续发送新的版本、编辑基线、Blame、定位及工具栏元数据，所有写入仍使用原捕获上下文和真实状态校验。

每个服务器只持有当前发布。正文身份可沿用，但字符串引用使用这次捕获的正文，不保留上一发布或历史链。完整载荷和省略正文的载荷分别按需序列化。浏览器明确携带自己持有的 contentId 才可收到 reuseContent；不带身份的请求、重载、目标边界改变、Diff 和提示文档均返回完整载荷。文档与 Markdown 资源所有权属于同一原子发布，旧图片请求仍须核对资源上下文。

DocumentTransport 仅保存最后一次接受的磁盘正文，独立于可写 Monaco 草稿与撤销栈，不建立每标签的正文缓存。响应先核对请求/文档代次和取消，再接受内容；正文缺失时最多重试一次完整请求，重试仍校验代次。空字符串是有效正文，不能把省略正文的元数据帧当作空文件。切换正文、Diff、提示或页面卸载后释放旧传输缓存，关闭标签沿用 SourceEditing 的模型释放路径。元数据发布不得覆盖脏模型的正文、撤销检查点或原保存基线；干净模型仍按原规则接受重新核验的编辑元数据。

C1 只减少重复正文序列化、传输和解析，后端仍按既有规则重读并验证磁盘；没有跳过 F5 的状态检查，也没有实现跨标签正文缓存或新的草稿持久化策略。验证需覆盖身份边界、过期响应/重试、空正文与完整重载，并在真实 Monaco 检查草稿/撤销/关闭。后端与协议基准、浏览器功能验证及原生桌面进程树性能分别报告。

## 标签会话与模型驻留分离（C2）

SourceEditing 的标签会话可只保留路径、编辑基线和状态，不必始终持有 Monaco 模型。没有任何编辑历史的模型按最近显示顺序保留，默认最多 4 个、正文估算 4 MiB（getValueLength × 2）；使用长度接口，不为预算物化全文。此预算仅约束可重建模型的正文，不包括 token、worker、编辑器内部结构或应用总内存。

回收仅发生在窗格完成模型切换之后。当前活动或仍绑定的模型、正在保存、带保存错误、标签锁/磁盘写锁保护的模型均不能回收；保护存在时允许暂时超出预算，下次模型切换再检查。回收前解除订阅；会话继续提供轻量元数据，fileDraft 对没有驻留模型的会话返回 null。再次打开必须使用本次后端重新捕获的文档创建新模型与编辑基线，不从旧会话缓存恢复正文；旧模型的保存回执不得影响新模型。关闭标签会同时移除轻量会话。

任何编辑事件或显式草稿恢复都会使模型持续归标签所有，即使之后保存或撤销到干净状态，也不能按“当前无脏内容”回收并丢失撤销/重做链。自动跟随磁盘的 setValue 不属于用户编辑历史；已有历史标记不会因刷新而清除。滚动、光标和折叠视图仍由 SourceTabs 管理，与正文模型的驻留分开。没有新增草稿上限、降低预览上限或自动丢弃编辑。

验收同时覆盖连续浏览、最近模型重访、被回收模型重建、视图恢复及干净状态下的撤销历史。浏览器 GC 后的 JS 活跃堆只能反映对应渲染器的保留数据，不能视为完整 Grove/WebView 进程树内存；回收带来的重新解析/着色成本需单独报告，不以降低内存推断 CPU 同时降低。

## 结构化 Diff 与后备文本（D1）

BufferDiff 从已锁定的 libgit2 1.8 原生 patch 直接复制 hunk 的四个行范围整数，构建 DiffHunk；结构定义与调用约定依据官方 [git_diff_hunk](https://github.com/libgit2/libgit2/blob/v1.8.4/include/git2/diff.h) 和 [git_patch_get_hunk](https://github.com/libgit2/libgit2/blob/v1.8.4/include/git2/patch.h)。不保留原生 hunk 指针。原生 patch、buffer 在本次计算的 finally 中释放，版本/导出不匹配仍回退 CLI。既有输入阈值、取消和 CPU 执行额度不变。

结构化范围和 CLI patch 解析共用同一行配对/行内高亮构建器，校验负数、溢出、范围顺序、未变化区域及完整覆盖。行特征用两个 UTF-16 单元组成的 uint 表示原有 ordinal bigram，保持原来的去重、裁剪与相似度语义；不是把字符对替换为可能碰撞的摘要，也不改成 Rune 或可见字符计数。

共享 DiffComputation 提供只读 SideBySideDiff 和线程安全的延迟 patch 文本。原生路径仍生成并复制 UTF-8 patch 字节以保留兼容输出，但普通文档/合并布局/Blame 行映射不再为取得范围而解码和正则解析完整 patch。延迟工厂只能捕获托管字节和空白选项，不能引用仓库、原生句柄、取消源或标准化输入；读取文本不重新执行 Git/Diff。大输入的 CLI 路径仍读取并解析字符串，不声称已经消除全部 patch 中转。

RepositoryDocument.Text 保留原有构造/读取/with/JSON 契约；只读 Text 时才兑现后备文本，显式 with { Text = ... } 必须清除旧的延迟视图。文档复制可共享同一不可变延迟值，新的磁盘状态不能改变旧文档的文本。字段序列化顺序保持原样；EditorServer 省略 Diff.Text 的序列化路径不能意外兑现该值。历史/工作区上下文、评论身份和写令牌仍由各自读取捕获，不从延迟显示文本生成写入授权。

验收分别测结构化文档读取、主动读取完整 patch 的控制路径及普通源码，核对完整序列化结果一致；不以局部调用分配下降推断应用常驻内存或空闲 CPU 改善。Git hook 测试的就绪信号应在写入关闭后原子发布，文件刚出现不表示已完成握手；不得用放宽实际提交/索引断言或跳过失败测试消除竞争。

## 历史摘要与有界详情缓存（D2）

主历史列表通过 QueryHistorySummariesAsync 分页读取，CommitEntry.HasFullMessage=false 明确表示正文尚未加载；列表不被详情结果回填。原有 HistoryAsync/QueryHistoryAsync 保留完整说明契约，文件历史面板继续使用它以保留逐行完整 tooltip。摘要与完整列表的游标身份分开，全文/正则查询仍搜索完整提交说明，不能把摘要加载变成仅搜索标题。分页、图布局及历史数量上限不变。

选择提交或两个固定修订比较时，CommitDetailsAsync/CompareDetailsAsync 在同一仓库句柄和 CPU 执行额度内读取所需说明与文件列表，避免拆成多次打开仓库后抵消 CPU 收益。视图模型最多保留当前两端详情。等待期间显示加载状态，失败显式报告，F5 完整刷新可重试；文件列表与说明完成后一起核对仓库和提交请求代次，换仓/重新筛选/更换选择后的迟到结果不能发布。旧 IRepositoryReader 实现通过默认方法兼容已有读取接口；完整行无需额外读取说明。与工作区比较仍保留实时 Git 读取。

RepositoryReader 独占两个已完成结果 LRU：说明最多 64 项、估算 1 MiB；固定树变化列表最多 32 项、估算 4 MiB。估算计入键、UTF-16 字符串和条目开销，不等于堆实测；单项超预算照常返回但不保留。缓存值只含托管字符串或只读记录集合，不保存 Repository/Commit/Tree、原生句柄、任务、异常或取消源。Dispose 同步关闭缓存并释放值，之后完成的读取不能重新填充。历史游标与 UI 当前显示的数据不属于这两个额外缓存预算。

树变化缓存达到容量后增加准入判断：比较新结果与它将挤出的所有 LRU 条目的近期访问频率，只有更频繁时才替换；频率相同保留现有结果，拒绝缓存不影响本次返回值。统计表仅在首次容量压力时分配，固定 1 KiB，不保留键或路径；四行 byte 计数上限 15，每 128 次观测减半，饱和命中也推进老化，避免旧热点永久占用缓存。首次启用时给现有条目各记一次，并计入该观测窗口；之后每次查询记一次。计数是近似准入依据，哈希冲突只能改变命中率，取值仍由完整键的精确比较决定。设计参考 [TinyLFU 频率与老化说明](https://github.com/ben-manes/caffeine/blob/master/caffeine/src/main/java/com/github/benmanes/caffeine/cache/FrequencySketch.java)，未引入其依赖或照搬实现；不宣称所有工作集都能命中。说明缓存继续使用普通 LRU。

树列表按锁定 LibGit2Sharp 的 [TreeChanges.Count/枚举契约](https://github.com/libgit2/libgit2sharp/blob/0.32.0/LibGit2Sharp/TreeChanges.cs) 预分配结果数组，并在同次遍历中计量容量。OldPath 与 Path 完全相等时共用该结果中的不可变字符串，仅计一次字符存储；不同路径仍分别保存/计量。不建立全局字符串池，不改变字面路径、顺序、状态、比较类型或 JSON 输出。预算中的条目固定开销保守计入，额外的统计表单独列明；验收同时覆盖超容量轮转、单次扫描、热点切换和有意哈希碰撞。

每次命中前仍新开仓库并解析引用/缩写，说明以私有 Git 目录和完整提交 SHA 为键；变化列表以私有 Git 目录、实际两侧树 SHA 和 ComparisonKind 为键。第一父树每次重新解析，避免浅克隆边界变化时沿用旧结果；关联 worktree 不共用条目。树列表只缓存固定 SimilarityOptions.None 的字面路径/状态，不含 patch、文本转换或重命名检测；该边界依据锁定 libgit2 的 [tree-to-tree 实现](https://github.com/libgit2/libgit2/blob/v1.8.4/src/libgit2/diff_generate.c)。改变比较选项或依赖版本时重新审查键及相关测试。工作区、索引、可变引用本身和仓库快照不在缓存内；固定提交比较与工作区比较须分别测试。

真实性能验收区分首次读取、容量以内重访、完整历史浏览和工作区控制组。减少常驻说明需核对列表仍完整、正文可按需取回；缓存命中加速不能推广到冷读、完整应用内存或原生交互响应。
